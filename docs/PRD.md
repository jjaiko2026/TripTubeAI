# TripTube AI — 제품 요구사항 문서 (PRD)

## 1. 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | TripTube AI |
| 네이밍 유래 | Trip + YouTube + AI |
| 한 줄 정의 | 유튜브·블로그에 흩어진 여행 정보를 AI가 대신 검색·정리해서, 클릭 한 번으로 완성된 여행 일정을 만들어주는 웹앱 |
| 문서 버전 | v1.0 (2026-08-10) |

## 2. 문제 정의 (Problem Statement)

여행을 계획하는 사람들은 정보를 얻기 위해 유튜브 영상을 여러 개 검색해서 시청한다. 그 과정에서 아래와 같은 불편함이 발생한다.

- 영상을 이 영상 저 영상 넘겨보다가 **앞서 본 영상의 내용을 잊어버림**
- 여러 영상·블로그에서 얻은 정보가 **정리되지 않고 흩어져 있음**
- 정보 탐색 자체에 **많은 시간이 소요**됨 (검색 → 시청 → 메모 → 재검색 반복)
- 최종적으로 "결국 나는 무엇을 봤고, 무엇을 해야 하는지" **하나의 일정으로 귀결되지 않음**

## 3. 목표 (Goals)

1. 사용자가 여행 조건(여행지/인원/기간/시기/목적)만 입력하면, AI가 최근 1년 이내의 유튜브 영상·블로그 글을 조회하여 **이상적인 여행 일정을 자동으로 구성**한다.
2. 결과물에는 **참조한 유튜브 영상의 썸네일·링크**, **참조한 블로그 글 링크**를 함께 제시하여 신뢰도와 출처를 보여준다.
3. 실제로 이 서비스를 통해 여행을 다녀온 사용자들의 **후기**를 노출하여 사회적 증거(social proof)를 제공한다.
4. **대시보드**(방문자 수, 일정 생성 실행 횟수, 여행지별 평균 여행 비용 그래프)를 통해 서비스에 대한 신뢰를 형성한다.
5. 로그인 사용자에게는 실제 일정 생성 기능을, 비로그인 사용자에게는 예시 화면(데모)을 제공하여 가입 전환을 유도한다.

### Non-goals (이번 범위에서 제외)

- 실제 항공권/숙박 예약·결제 연동
- 다국어(영어 등) 지원 (1차는 한국어)
- 네이티브 모바일 앱

## 4. 타깃 사용자

- 여행 계획 초기 단계에서 유튜브·블로그를 순회하며 정보를 모으는 20~40대 개인/그룹 여행 준비자
- 짧은 시간 안에 "그럴듯한 초안 일정"을 받아 이를 다듬어 쓰고 싶은 사용자

## 5. 핵심 사용자 흐름 (User Flow)

```
[방문] → 랜딩 페이지
   ├─ 비로그인 → 예시(데모) 일정 화면 열람 → 로그인 유도
   └─ 로그인 → 여행 조건 입력 폼
                  ↓
        [여행지 / 인원 / 박수 / 여행 시기(월) / 여행 목적] 입력
                  ↓
        AI가 최근 1년 유튜브 영상 + 블로그 글 조회·분석
                  ↓
        일자별 여행 일정 생성 (장소, 이동 동선, 추천 이유)
                  ↓
        참조 유튜브 썸네일/링크, 블로그 링크 함께 노출
                  ↓
        일정 저장 / 공유 / (여행 후) 후기 작성
```

## 6. 기능 요구사항 (Functional Requirements)

### 6.1 랜딩 페이지 (비로그인)
- 문제 상황(유튜브 검색을 전전하는 모습)을 시각적으로 소개
- 서비스가 그 문제를 어떻게 해결하는지 설명 (Before/After)
- **예시 일정 화면**을 정적/샘플 데이터로 미리보기 제공
- 방문자/실행 통계, 여행지별 평균 비용 그래프 등 신뢰 지표 노출
- 여행 후기 리스트 노출
- 로그인/회원가입 CTA

### 6.2 인증
- 로그인 사용자만 실제 "일정 생성" 기능 이용 가능
- 비로그인 사용자는 조회만 가능 (일정 생성 폼 진입 시 로그인 요구)

### 6.3 여행 일정 요청 폼
입력 항목:
- 여행지 (국내/해외 지역)
- 구성원 (인원 수 및 구성: 혼자/친구/가족/연인 등)
- 숙박 일수 (몇 박 몇 일)
- 여행 시기 (월)
- 여행 목적 (힐링, 맛집, 액티비티, 문화/역사, 쇼핑 등 다중 선택)

### 6.4 AI 일정 생성 엔진
- 입력 조건 기반으로 최근 1년 이내 발행된 관련 유튜브 영상 검색
- 관련 블로그 글 검색
- 수집된 콘텐츠에서 장소/동선/맛집/팁 등 핵심 정보를 추출·요약
- 일자별(Day 1, Day 2 …) 일정표로 재구성 (시간대별 추천 포함)
- 각 추천 항목에 근거가 된 출처(영상/블로그) 연결

### 6.5 결과 화면
- 일자별 타임라인 UI
- 참조 유튜브 영상: 썸네일 + 제목 + 채널명 + 원본 링크
- 참조 블로그 글: 제목 + 요약 + 원본 링크
- 일정 저장, 공유(링크 복사), PDF/이미지 내보내기(추후)

### 6.6 후기(리뷰)
- 일정을 이용해 여행을 다녀온 사용자가 후기 작성 (평점 + 텍스트 + 사진)
- 랜딩 페이지 및 별도 후기 목록 페이지에 노출

### 6.7 대시보드 (신뢰 지표)
- 누적 방문자 수 / 일정 생성 실행 횟수 (시계열 그래프)
- 여행지별 평균 여행 비용 (막대/비교 그래프)
- 인기 여행지 Top N
- 목적별(힐링/맛집/액티비티 등) 비중

## 7. 정보 구조 (Sitemap)

```
/                      랜딩 (비로그인: 데모, 로그인: 대시보드 요약 + CTA)
/login                 로그인
/plan/new              여행 조건 입력 폼 (로그인 필요)
/plan/[id]             생성된 일정 결과
/plan/[id]/example     비로그인용 예시 일정
/reviews               여행 후기 목록
/dashboard             통계 대시보드
```

## 8. 데이터 모델 (개략)

- **User**: id, email, name, createdAt
- **TripRequest**: id, userId, destination, members, nights, month, purposes[], createdAt
- **Itinerary**: id, tripRequestId, days[{day, items[{time, title, description, sourceType(youtube|blog), sourceId}]}]
- **SourceVideo**: id, youtubeVideoId, title, thumbnailUrl, channelName, url, publishedAt
- **SourceBlog**: id, title, summary, url, publishedAt
- **Review**: id, userId, itineraryId, rating, content, photos[], createdAt
- **UsageStat**: date, visits, itinerariesGenerated
- **DestinationCost**: destination, avgCostPerPerson, sampleSize

## 9. 기술 스택 (안)

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js (App Router) + TypeScript |
| 스타일 | Tailwind CSS + shadcn/ui |
| 차트 | Recharts |
| 인증 | (프로덕션) Clerk — 1차 데모는 임시 세션 기반 로그인 |
| 데이터 | (프로덕션) Postgres(Neon, Vercel Marketplace) — 1차 데모는 목(mock) 데이터 |
| 외부 API | YouTube Data API v3, 블로그 검색 API(예: 네이버 검색 API), AI 모델(Vercel AI Gateway) |
| 배포 | Vercel |

> 1차 구현은 **실제 API 키 없이도 전체 흐름을 시연**할 수 있도록 목 데이터 기반으로 제작하고, 실제 연동에 필요한 지점(YouTube API, 블로그 검색 API, AI 모델, 인증, DB)은 인터페이스로 분리하여 이후 실제 키/서비스만 연결하면 되도록 구성한다.

## 10. 성공 지표 (KPI, 제안)

- 여행 조건 입력 → 일정 생성 완료율
- 생성된 일정 저장/공유율
- 재방문율 및 후기 작성률
- (장기) 실제 예약 전환 연동 시 전환율

## 11. 리스크 및 오픈 이슈

- 유튜브/블로그 콘텐츠 저작권 및 이용약관 준수 (임베드/링크 형태로만 노출, 무단 재배포 금지)
- YouTube Data API 쿼터 제한 → 캐싱 전략 필요
- AI가 생성한 일정의 사실 정확성(영업시간, 폐업 여부 등) 검증 어려움 → "정보는 참고용이며 최신 정보를 다시 확인하세요" 안내 필요
- 블로그 검색 API 선정 필요 (네이버/카카오 등 국내 서비스 vs 범용 검색)

## 12. 향후 로드맵

1. **Phase 1 (현재)**: 목 데이터 기반 전체 플로우 데모 (UI/UX 완성)
2. **Phase 2**: YouTube Data API, 블로그 검색 API, AI Gateway 실연동
3. **Phase 3**: 실사용자 인증(Clerk) + DB(Postgres) 연동, 후기/대시보드 실데이터화
4. **Phase 4**: 일정 공유, PDF 내보내기, 예약 연동 검토
